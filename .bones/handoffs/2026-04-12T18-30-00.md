## Context for Next Session

### The actual performance bug
`ImplementationProvider._findSubclassLocations` and `_findMethodOverrideLocations` (definitionProvider.ts:389-452) iterate all source files and call `this._program.getParseResults(sourceFileInfo.uri)` on each. This triggers `_bindFile` (parsing + binding + import resolution) for every user-code file. With no `pyrightconfig.json` at workspace root, Pyright tracks all 1,284 Python test samples as user code. Binding all of them on cold cache takes >30s, exceeding the MCP server's hardcoded 30s timeout (mcp-server.ts:200).

`TypeHierarchyProvider.getSubtypes` (typeHierarchyProvider.ts:149-169) has the identical pattern and same issue.

`ReferencesProvider` avoids this with a string pre-filter on `sourceFileInfo.contents` (line 256) — `contents` reads file text from disk WITHOUT binding. Files that don't contain the symbol name are skipped entirely.

### Why the import-graph approach failed
The import graph (`importedBy`) is populated during binding. To use it as a pre-filter, ALL files must be bound first — which IS the bottleneck. Chicken-and-egg.

### Proposed but unimplemented approach: string BFS
Use `sourceFileInfo.contents` (no binding needed) to string-scan for the target class name. Only bind files whose text contains it. For transitive subclasses (e.g., `GoldenRetriever(Dog)` where target is `Animal`), BFS: finding `Dog` as a subclass adds "Dog" to the search queue, next pass finds files containing "Dog". This is the same pattern ReferencesProvider uses, extended with BFS for transitivity.

User lost trust in this approach after the import-graph failure. Next session should prototype and PROVE it works (measure timing, test on cold cache via MCP) before committing to production code.

### Key finding: `sourceFileInfo.contents` is available without binding
`getFileContent()` in sourceFile.ts reads from: (1) open file buffer, (2) cached parsed content, (3) filesystem. No parsing or binding triggered. This is why ReferencesProvider's string pre-filter is fast on cold cache.
