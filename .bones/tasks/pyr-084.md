## Context

First phase of Phase 5.5. Build the Node.js proxy that replaces `bin/start-server.sh`, owns the Pyright spawn, and serves both LSP and MCP protocol modes through a shared backend. Add plugin LSP config so Claude Code uses our dev Pyright for Python files.

## Requirements

R1, R2, R3, R4 from parent epic pyr-tcv.

## Success Criteria

- [x] Node.js proxy entry point replaces `bin/start-server.sh`
- [x] `--lsp` flag: LSP JSON-RPC passthrough works (diagnostics flow from dev Pyright)
- [x] `--mcp` flag: MCP server works (existing tool behavior preserved)
- [x] Shared Pyright via Unix socket + PID file — one Pyright process serves both modes
- [x] Any disconnect kills Pyright child (PID gone after close)
- [x] Plugin `lspServers` config in plugin.json, dev build provides Python LSP
- [x] `npm run typecheck` clean

## Gate

- `npm run typecheck` clean
- Plugin LSP config works: diagnostics flow from dev Pyright in Claude Code
- MCP tools still work through proxy

## Demo

Show diagnostics flowing from our dev build in Claude Code, MCP tool call working through proxy, single Pyright PID, clean teardown on disconnect.

## Key Considerations

- `mcp-server.ts` currently spawns Pyright directly — the proxy extracts that spawn logic
- `resolve-langserver-path.ts` already handles path resolution, reuse it
- Webpack config copies `pyright-langserver.js` to dist — proxy needs to be in dist too
- The `--mcp` path must preserve all existing MCP behavior (lsp() tool, semantic token decoding, didOpen flow)
